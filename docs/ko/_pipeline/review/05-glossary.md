# 05챕터 용어 후보 (F# 전문가 검수, 후보 모드)

`docs/ko/GLOSSARY.md` 는 편집하지 않았다(다른 챕터 전문가와 동시 작업 중).
아래 행을 알파벳 순 위치에 그대로 삽입하면 된다. 기확정 항목 중 바꿀 것은 없다.
`collection`(컬렉션)은 이미 확정돼 있고 "5챕터 본론" 표시도 붙어 있어 그대로 쓴다.

## 확정 제안 (그대로 삽입)

| 영어 | 한국어 표기 | 비고 |
|---|---|---|
| accumulator | 누적값 | `fold` 의 상태. 코드에서는 `acc`. MS ko 는 "누산기"이나 하드웨어 레지스터 뉘앙스가 강해 쓰지 않는다. 문맥에 따라 "상태"로 풀어 쓰는 것도 허용 |
| aggregation function | 집계 함수 | `sum`, `average`, `max` 처럼 컬렉션을 값 하나로 줄이는 함수. LINQ 의 `Aggregate` 에 대응하는 것은 `List.fold` 다 |
| `Array` | `Array` | 번역하지 않는다. 즉시 평가되는 고정 길이 연속 메모리. 타입 표기는 `'a array` 또는 `'a[]`. 다차원용 모듈은 `Array2D`/`Array3D`/`Array4D` |
| `comparison` constraint | `comparison` 제약 | 시그니처의 `when 'a : comparison`. 순서 비교가 가능해야 한다는 뜻. `Set`/`sortBy`/`maxBy` 가 요구한다. `equality` 제약보다 강하다 |
| cons operator | cons 연산자 | `::`. 라틴 표기 고정. "콘즈"로 음차하지 않는다. 리스트 맨 앞에 원소 하나를 붙이는 일만 하며, 우선순위가 `\|>` 보다 높다 |
| eager evaluation | 즉시 평가 | `List`/`Array` 의 평가 방식. 대비어는 지연 평가 |
| `equality` constraint | `equality` 제약 | 시그니처의 `when 'a : equality`. `=` 비교가 가능해야 한다는 뜻. `distinct`/`distinctBy`/`groupBy`/`countBy` 가 요구한다 |
| `fold` | `fold` | 모듈 함수 이름은 번역하지 않는다. "접기"·"축약" 쓰지 않음. `List.fold` 의 `folder` 는 (상태, 원소) 순, `List.foldBack` 의 `folder` 는 (원소, 상태) 순이며 인자 순서도 `folder`→리스트→초기값 으로 뒤집힌다 |
| `folder` | `folder` | `fold`/`foldBack` 에 넘기는 함수의 이름. 번역하지 않는다. `List.reduce` 의 같은 자리 매개변수는 FSharp.Core 에서 `reduction` 이므로 `reduce` 를 설명할 때 `folder` 라고 부르지 않는다 |
| head | 머리 | 비어 있지 않은 리스트의 첫 원소. 첫 등장 1회 `머리(head)` 병기. "헤드"로 음차하지 않는다. 함수 이름 `List.head`/`List.tryHead` 는 번역하지 않는다 |
| identity function | 항등 함수 | `id : 'a -> 'a`. `fun x -> x` 와 같다 |
| lazy evaluation | 지연 평가 | 값을 실제로 필요할 때까지 만들지 않는 것. `Seq` 와 LINQ 의 평가 방식. 6챕터 본론 |
| linked list | 연결 리스트 | F# `List` 의 실제 구조. 앞에 붙이기는 싸고 인덱스 접근은 비싸다 |
| `List` | `List` | 번역하지 않는다. F# 의 불변 연결 리스트 타입이자 그 지원 모듈 이름. .NET 의 `List<'T>` 와 다른 것이므로 "리스트"라고만 쓸 때는 F# 쪽을 가리킨다 |
| list comprehension | 리스트 컴프리헨션 | `[ for x in ... do ... ]`. 정착된 역어가 없어 음차를 택한다. "리스트 내포"는 하스켈 계열 문헌에만 쓰이고 독자가 원서 색인과 대조하기 어렵다. F# 명세는 이 문법을 "list expression"(리스트 식)이라 부르고 원서는 List Comprehension 이라 적는다 |
| partial function | 부분 함수 | 가능한 입력 전부에서 값을 돌려주지 못하는 함수. 빈 리스트에서 예외를 던지는 `List.reduce`/`List.head`/`Seq.skip` 이 그것이다. 이름이 비슷한 부분 적용(partial application)과는 다른 개념이므로, 두 용어가 한 챕터에 함께 나오면 부분 함수 쪽 첫 등장에서 원어를 병기하고 "부분 적용과는 관계가 없다"를 한 절 덧붙인다(`docs/ko/06-reading-data-from-file.md:9` 가 그 형태다). "부분적 함수" 쓰지 않음 |
| predicate | 술어 | `'a -> bool` 형태의 함수. 문장에서 함수임을 드러내야 하면 "술어 함수"로 늘려 쓴다. MS ko 는 "조건자"이나 커뮤니티 통용이 아니고, "조건 함수"는 가드 절의 조건과 헷갈린다. 논리학·전산학에서 정착된 "술어"를 택하고 첫 등장에 시그니처를 함께 보인다 |
| range expression | 범위 식 | `[1..5]`, `[0..5..20]`. MS ko 표기와 일치 |
| `reduce` | `reduce` | 번역하지 않는다. 상태와 원소의 타입이 같은 `fold` 의 특수한 경우이고, 첫 원소를 초기 상태로 쓰므로 그 원소는 함수를 거치지 않는다. 부분 함수이며 `List.tryReduce` 는 없다 |
| `ResizeArray<'T>` | `ResizeArray` | 번역하지 않는다. .NET `List<'T>` 의 F# 타입 약어이며 가변 배열이다. F# 의 `List` 와 정반대 성격이므로 둘을 같은 문장에서 "리스트"로 뭉개지 않는다 |
| `Seq` | `Seq` | 번역하지 않는다. 지연 평가되는 시퀀스 타입이자 모듈. .NET 의 `IEnumerable<'T>` 와 같은 것이다. 서술문에서 값을 가리킬 때는 "시퀀스" |
| `Set` | `Set` | 번역하지 않는다. "집합"으로 풀지 않는다. 정렬 컬렉션이므로 원소가 값의 비교 순서로 재배치되고 `comparison` 제약을 요구한다 |
| tail | 꼬리 | 머리를 뗀 나머지 리스트. 빈 리스트일 수 있다. 첫 등장 1회 `꼬리(tail)` 병기. "테일"로 음차하지 않는다. 11챕터의 꼬리 재귀(tail recursion)와 같은 낱말이나 다른 개념이므로 그 챕터에서 구분해 쓴다 |
| value restriction | 값 제한 | 매개변수 없는 `let` 바인딩이 제네릭 타입으로 유추될 때 나는 오류 FS0030. 컴파일러 한국어 메시지도 "값 제한"이다. `[]` 같은 인자 없는 케이스는 자동 일반화되므로 값 제한에 걸리지 않고, `let e = List.rev []` 처럼 함수 적용 결과를 묶을 때 걸린다 |

## 등재 보류

| 영어 | 표기 후보 | 보류 이유 |
|---|---|---|
| statically resolved type parameter (SRTP) | 정적으로 결정되는 타입 매개변수 (SRTP) | 05챕터 노트가 `List.sumBy` 시그니처의 `^b` 를 그대로 보여 주기만 하고 용어를 쓰지 않는다. `^` 표기를 한 절로 설명하기로 하면 이 표기로 등재하고, 아니면 9챕터로 미룬다 |

## 판단 근거를 남긴 항목

### `partial function` → 부분 함수 (병기 + 대비 문장 유지)
- 다른 역어를 찾는 안(예: "불완전 함수", "일부 입력 함수")은 정착된 말이 아니고 원서 색인·검색과 끊긴다.
- 원어 유지 안(`partial function`)은 한 챕터에 세 번 이상 나오는 용어라 문장이 무거워지고,
  같은 노트가 이미 `부분 적용`을 한국어로 쓰고 있어 표기 계열이 어긋난다.
- "부분 함수"는 수학·전산학에서 이미 정착된 역어다(전 함수 total function 의 대비어).
- 따라서 표기는 부분 함수로 두고, 혼동은 표기가 아니라 서술 규칙으로 막는다.
  1. 각 챕터 첫 등장에서 `부분 함수(partial function)` 로 병기한다.
  2. 한 챕터에 부분 적용도 나오면 부분 함수 첫 등장에 "부분 적용과는 관계가 없다"를 붙인다.
  3. "부분"만으로 줄여 쓰지 않는다.
- 05챕터는 부분 적용이 한 번도 나오지 않아 규칙 1 만 적용되고, 6챕터는 이미 규칙 2 를 지키고 있다.
  11챕터에서 꼬리 재귀와 함께 다룰 때도 같은 규칙을 쓴다.

### `predicate` → 술어
- MS ko "조건자"는 `System.Predicate<T>` 문서 계열에서만 보이고 F# 커뮤니티 문서에서 거의 쓰이지 않는다.
- "조건 함수"는 서술로는 읽히지만 `when` 가드 절의 조건과 구분이 되지 않는다.
- "술어"는 술어 논리에서 온 정착 역어이고 짧다. 독자가 낯설 수 있으므로 첫 등장에서
  `'a -> bool` 형태의 술어(predicate) 처럼 시그니처를 함께 보이는 05챕터의 현재 서술을 표준으로 삼는다.

### `list comprehension` → 리스트 컴프리헨션
- 파이썬 문서·강의를 통해 "리스트 컴프리헨션"이 국내에서 가장 널리 통용된다.
- "리스트 내포"는 뜻이 바로 오지 않고 사용층이 좁다.
- 표기 원칙(정착된 역어가 없으면 음차)에 그대로 맞는다.

### `head`/`tail` → 머리/꼬리
- 노트가 `h :: t`, `first :: rest` 를 "이름 자체에 의미는 없다"고 설명하므로,
  개념을 가리키는 한국어와 함수 이름(`List.head`)을 분리해 두는 편이 읽기 쉽다.
- "헤드/테일"은 자료구조 노드 이름 느낌이 강하고, 11챕터 꼬리 재귀와의 낱말 연결도 끊긴다.

### `value restriction` → 값 제한
- FSI 한국어 오류 메시지가 그대로 "값 제한: 값 'x'에 유추된 제네릭 형식이 있습니다" 다.
  컴파일러 메시지와 노트 표기를 일치시키는 것이 검색에 유리하다.
