# 05챕터 최종 검수 (용어·문법·문체·구조)

대상: `docs/ko/05-collections.md` (650줄, 실행 단위 6개)
기준: `docs/ko/GLOSSARY.md`(201행), `docs/ko/_pipeline/STYLE.md`
선행: `.cache/review/05-expert.md`(기술 검수), `.cache/review/batchB-glossary-merge.md`(용어집 병합)

기술 내용은 재검토하지 않았다. 아래는 표기·문장·구조만 본 결과이며,
전문가 지시서가 제시한 교체 문장도 검수 대상에 넣어 4절에 따로 정리했다.
줄 번호는 모두 수정 전 원본 기준이다. 같은 줄에 여러 항목이 걸린 경우 4절의 교체문이 최종형이다.

인용 예외를 먼저 밝힌다. 180-181줄과 새로 들어가는 FS0030 예시 블록의 주석은 컴파일러 메시지
인용이므로 "형식", "값 제한" 같은 원문 표기를 그대로 둔다(용어집 머리말 14줄). 고치지 마라.

### 병기 (첫 등장 1회 규칙)

중복 병기는 없다. 값 제한·머리·꼬리·빠짐없는 패턴 매칭·술어·부수 효과·부분 함수·컬렉션은 모두
첫 등장 1회로 정확히 처리되어 있다. `부분 적용` 은 이 챕터에 0회이므로 용어집 136행이 요구하는
"부분 적용과는 관계가 없다" 한 절은 붙이지 않아도 된다(263줄 그대로 두라).
아래는 누락이다.

- [05-collections.md:15] `즉시 평가` 병기 누락 → "- `Array` 는 즉시 평가(eager evaluation)되는 고정 길이 연속 메모리다. 인덱스 접근이 빠르고 수치 계산에 유리하다. 2·3·4차원 배열용 모듈이 따로 있다." (용어집 65행이 `eager evaluation` 을 5챕터 소유로 적었다. 대비어 `지연 평가` 는 위 14줄 수정문에 병기를 넣었다 — 06챕터 8줄이 같은 방식으로 병기한다)
- [05-collections.md:3] `고차 함수` 병기 누락 → "... 그 타입마다 붙은 모듈에 미리 만들어 둔 고차 함수(higher-order function)가 잔뜩 들어 있어서 ..." (02챕터 249줄, 03챕터 7줄이 각각 병기했다. 챕터마다 1회 허용 규칙에 따라 05도 첫 등장에 붙인다. 135줄의 "고차 함수다" 는 그대로 둔다)

### `folder` / `reduction` 분리 확인

용어집 81·153행이 두 이름을 나눠 등재했다. 기계 대조 결과 `folder` 가 나오는 줄은 9개이고
그중 411·633줄만 `reduce` 자리에 잘못 쓰였다(전문가 지시서와 같은 지적). 나머지 7줄
(197·200·205·211·212·222·632)은 모두 `fold`/`foldBack` 자리라 정확하다.
411·633줄 교체문은 4절 [권장5] 에 적었다. 교체 후 `reduction` 은 2곳, `folder` 는 `fold` 계열에만
남아 뒤섞이는 자리가 없다.
