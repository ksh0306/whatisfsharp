### [6] `inline` + SRTP 코드 교체 — 코드 위쪽 산문이 낡는다
교체 코드 자체(`let inline nightlyFee (nights: 'a when 'a: (member Value: int)) =` + `decimal nights.Value * 35000M`)와 주석 `// nights: ^a -> decimal when ^a: (member Value: int)` 는 그대로 쓴다. 실행 검증은 이 블록 하나만 바뀌므로 `09-smartctor` 단위를 다시 돌려 `Ok 70000M` 출력과 주석이 맞는지 확인하라. `printfn` 줄은 손대지 않으니 열 정렬은 그대로다.

문제는 195줄 산문이다. 지금 문장은 "정적으로 확인되는 타입 매개변수(SRTP)에 멤버 제약을 직접 적는 것"이라고 하는데, 새 코드는 `^a` 가 아니라 `'a` 로 적는다. 산문과 코드가 어긋나므로 단락을 함께 갈아라.
현재(195줄): "주석을 달지 않고도 멤버 조회를 컴파일하는 길이 하나 있다. 함수를 `inline` 으로 선언하고 정적으로 확인되는 타입 매개변수(statically resolved type parameter, SRTP)에 멤버 제약을 직접 적는 것이다. `Value: int` 프로퍼티가 있는 타입이면 무엇이든 받는다."
→ 수정: "타입 주석을 달지 않고도 멤버 조회를 컴파일하는 길이 하나 있다. 함수를 `inline` 으로 선언하고 타입 매개변수에 멤버 제약(member constraint)을 직접 적는 것이다. 코드에는 `'a` 로 적지만 `inline` 함수의 타입 매개변수는 호출 지점마다 확정되므로, FSI 시그니처에는 정적으로 확인되는 타입 매개변수(statically resolved type parameter, SRTP)를 뜻하는 `^a` 로 나타난다. `Value: int` 프로퍼티가 있는 타입이면 무엇이든 받는다."
(병기는 SRTP 1회, 멤버 제약 1회로 각각 노트 안에서 유일하다.)

471줄 요약도 코드와 같은 문법으로 맞춘다(전문가가 "같이 손대는 것이 좋다"고만 적었으므로 문장을 지정한다).
현재: "매개변수에 타입 주석을 달거나, `inline` 함수에 `^a : (member Value : int)` 제약을 손으로 적어야 한다. 실측 시그니처는 `nights: ^a -> decimal when ^a: (member Value: int)` 다."
→ 수정: "매개변수에 타입 주석을 달거나, `inline` 함수의 타입 매개변수에 `'a when 'a: (member Value: int)` 제약을 손으로 적어야 한다. 실측 시그니처는 `nights: ^a -> decimal when ^a: (member Value: int)` 다."
205줄("`inline` 만 붙이고 `nights.Value` 라고 쓰면 여전히 오류 FS0072 다. 제약을 손으로 적어야 추론이 성립한다.")은 새 코드에서도 그대로 성립하므로 손대지 않는다.
