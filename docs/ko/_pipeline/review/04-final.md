### 오류·경고 번호 표기 (전문가안 적용 시 반드시 통일할 것)

현재 본문의 표기는 백틱 없이 "오류 FS0892"(203줄), "(오류 FS0222)"(490줄)다. 오류 번호는 코드 식별자가
아니므로 백틱을 쓰지 않는다. 전문가안은 `` `MSB4006` ``, `` `FS0222` ``, `` `FS0842` ``, `` `FS0039` `` 처럼
전부 백틱을 달고 있으니, 노트에 옮길 때 **모두 백틱을 떼고 "오류 FSxxxx" / "경고 FSxxxx" 형태로 적어라.**
해당 대상: 신규로 들어오는 MSB4006, FS0201, FS0248, FS0239, FS0842, FS0039, FS0222 언급 전부.
코드 블록 안의 컴파일러 메시지 인용(106·118줄)은 원문 그대로이므로 예외다.

### 병기

이 챕터의 병기는 8곳이다(3줄 solution·project·namespace·module·unit test, 23줄 assertion,
264줄 side effect, 354줄 structural equality). 용어집 머리말이 "챕터마다 1회까지"를 허용하므로
**이 챕터 안에서 중복된 병기는 없다.** 아래 세 곳만 보태고, 그 밖에는 병기를 늘리지 마라
(어셈블리·컴파일 순서·중첩 모듈·최상위 모듈·정규화된 이름·프로젝트 참조·순환 참조·테스트 러너·
부분 적용·판별 유니온은 병기 없이 한국어만 쓴다).

## 문법·문체

- [04:3] 둘째 문장이 한 문장에 병기 다섯 개와 "-고" 연결 세 개를 담아 늘어진다. 두 문장으로 끊는다.
  현재: "스크립트 파일 하나에 코드를 몰아넣는 단계를 벗어나, 솔루션(solution)과 프로젝트(project)로 경계를 긋고 네임스페이스(namespace)와 모듈(module)로 이름을 정리하고 xUnit 으로 단위 테스트(unit test)를 짜는 방법이 나온다."
  수정: "스크립트 파일 하나에 코드를 몰아넣는 단계를 벗어나는 방법이 나온다. 솔루션(solution)과 프로젝트(project)로 경계를 긋고, 네임스페이스(namespace)와 모듈(module)로 이름을 정리하고, xUnit 으로 단위 테스트(unit test)를 짠다."

- [04:9] 뒤 문장의 주어가 없어 "관례"가 무엇을 가리키는지 흐리다.
  현재: "코드 프로젝트는 `src/` 아래, 테스트 프로젝트는 `tests/` 아래에 둔다. .NET 생태계의 관례이고, 나중에 프로젝트가 늘어나도 구조가 유지된다."
  수정: "코드 프로젝트는 `src/` 아래, 테스트 프로젝트는 `tests/` 아래에 둔다. 이것이 .NET 생태계의 관례이고, 이렇게 두면 나중에 프로젝트가 늘어나도 구조가 유지된다."

- [04:20] 주술 불일치다. 동작하는 주체는 따옴표가 아니라 명령이다.
  현재: "- `-lang \"F#\"` 의 따옴표는 없어도 셸이 `#` 을 주석으로 보지 않으므로 동작하지만, 붙여 두는 편이 안전하다."
  수정: "- 따옴표를 빼도 셸은 낱말 첫 글자가 아닌 `#` 을 주석으로 보지 않으므로 명령은 그대로 동작한다. 그래도 `-lang \"F#\"` 처럼 붙여 두는 편이 안전하다."

- [04:75] "규칙은 … 있는 것이 아니라 … 적용된다"로 주어와 서술어가 두 번 어긋난다.
  현재: "이 \"위에서 아래로만 보인다\"는 규칙은 파일 사이에만 있는 것이 아니라 파일 안에서도 똑같이 적용된다."
  수정: "이 \"위에서 아래로만 보인다\"는 규칙은 파일 사이에만 적용되는 것이 아니다. 파일 안에서도 똑같다."

- [04:130] "대신"이 앞 문장과 논리적으로 이어지지 않는다(값을 못 두는 것의 보상이 아니다).

  현재: "- 네임스페이스에 담을 수 있는 것은 타입 선언, `open` 선언, 모듈뿐이다. 값이나 함수를 네임스페이스 바로 아래에 둘 수는 없다. 대신 여러 파일에 걸쳐 같은 네임스페이스를 쓸 수 있고, 모듈 이름은 파일이 달라도 한 네임스페이스 안에서 유일해야 한다."

## 원문 의존도

직역투나 원서 문장 구조가 그대로 보이는 대목은 없다. 원서 참조는 모두 "원서는 …", "원서의 조언이다"
같은 3인칭 서술로 처리되어 있고(7·35·50·150·171·259·263·329·415·428·482-483줄), 도구 명령과 출력 인용을
빼면 문장이 전부 새로 쓰였다. 코드 예제도 원서의 고객 승급 도메인을 수강생 도메인으로 갈아 놓았다.
