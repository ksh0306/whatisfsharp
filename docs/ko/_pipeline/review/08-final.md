### 권장

9. [08-functional-validation.md:742-747] 출력 라벨의 `누적` 이 본문 용어와 어긋난다.
   근거: 용어집 `accumulating errors` 행이 "'오류 누적'은 `accumulator`→누적값 과 겹쳐 `fold` 의 상태로
   읽히므로 쓰지 않는다"고 못 박았고, 이 챕터는 792-799줄에서 실제로 `List.fold` 의 상태를 다룬다.
   본문 표기는 "오류를 모으는 방식"/"첫 오류에서 멈추는 방식"이다.
   현재 → 수정 (코드 3줄과 기대 출력 주석 3줄을 함께 바꾼다)
   - `show "and! 누적" (validateSlip "" "maybe" "-")` → `show "and! 수집" (validateSlip "" "maybe" "-")`
   - `show "let! 중단" (validateSlipStopping "" "maybe" "-")` → `show "let! 멈춤" (validateSlipStopping "" "maybe" "-")`
   - `// and! 누적      반송 3건 — SampleId, Chilled, VolumeMl` → `// and! 수집      반송 3건 — SampleId, Chilled, VolumeMl`
   - `// let! 중단      반송 1건 — SampleId` → `// let! 멈춤      반송 1건 — SampleId`
   `and! 통과` 는 그대로 둔다.
   열 정렬 확인: 라벨은 `%-12s` 로 찍힌다. 세 라벨 모두 ASCII 5자 + 한글 2자 = 7자로 바뀌지 않으므로
   채움 폭(5칸)과 주석의 공백 6칸이 그대로다. 한글 글자 수도 셋 다 2자로 같아 터미널 폭도 어긋나지 않는다.

- `](examples/...)` 링크나 `docs/ko/examples` 경로는 없다. 코드 블록도 설명 사이사이에 흩어져 있다.
- 354-367줄 인용 안의 "형식"·"지정되었습니다" 는 용어집 머리말대로 고치지 않는다.
  다만 본문이 `형식` 을 "입력 문자열의 서식" 뜻으로 쓰고(231·239·824줄, `BadFormat`),
  인용 쪽 `형식` 은 type 을 뜻한다. 노트 전체가 type 을 언제나 "타입"으로 쓰므로 혼동은 없다고 보고
  수정 대상에서 뺐다. 새로 쓰는 문장에서도 type 을 "형식"으로 적지 마라.
