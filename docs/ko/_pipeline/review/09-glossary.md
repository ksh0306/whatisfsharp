# 09챕터 용어 후보 (F# 전문가 검수, 후보 모드)

`docs/ko/GLOSSARY.md` 는 읽기만 했고 편집하지 않았다(다른 챕터 전문가와 동시 작업 중).
아래 행을 알파벳 순 위치에 그대로 삽입하면 된다.

10챕터가 동시에 검수 중이고 `member` / `property` / `constructor` / `instance` / `struct` 를
대량으로 쓴다. 아래 행의 비고에 판단 근거를 남겨 두었으니 2b 병합에서 10챕터 후보와 맞춰 볼 것.

## 확정 제안 (그대로 삽입)

| 영어 | 한국어 표기 | 비고 |
|---|---|---|
| access modifier | 접근 지정자 | `private`/`internal`/`public`. MS ko F# 문서의 절 제목은 "액세스 제어"(Access Control)이고 MS ko C# 문서는 "액세스 수정자"이나, 노트는 통용 표기 "접근 지정자"를 택한다. "접근 제어자"·"액세스 수정자" 쓰지 않는다. 원서 p.122 는 이것을 "the private accessor"라 부르지만 accessor 는 보통 프로퍼티의 get/set 을 가리키므로 원서 표기를 옮기지 않는다. 컴파일러·FSI 메시지 인용에서는 원문의 "액세스"를 그대로 남긴다. 9챕터 본론, 10챕터 캡슐화 절과 공유 |
| companion module | 같은 이름의 모듈 | 타입과 같은 이름을 붙여 그 타입 전용 함수를 담는 모듈(`Option` 타입과 `Option` 모듈, `Nights` 타입과 `Nights` 모듈). 영어권에서도 정착된 용어가 아니고 원서·MS ko 모두 쓰지 않는다. 원서는 "a module with the same name as the type"으로 풀어 쓴다. 새 역어를 만들지 않고 "타입과 같은 이름의 모듈"로 풀어 쓰며, 문맥이 분명하면 "같은 이름의 모듈"로 줄인다. "동반 모듈"·"컴패니언 모듈" 쓰지 않는다. 9챕터가 두 곳(본문 235행, 258행)에서 "동반 모듈"을 쓰므로 고쳐야 한다 |
| heap allocation | 힙 할당 | 참조 타입 값을 만들 때 힙에 개체가 생기는 것. `[<Struct>]` 를 붙이면 없어진다. 7챕터 `voption` 후보 행의 "힙 할당이 없다"와 표기가 같다 |
| instance | 인스턴스 | 음차 고정. MS ko 도 "인스턴스". 9·10챕터 공통이고 1·2·3·6챕터가 이미 쓰고 있다 |
| member | 멤버 | 타입 안에 선언하는 `member`/`static member`. 음차 고정, MS ko 도 "멤버". 프로퍼티와 메서드를 아우르는 상위 낱말이므로 프로퍼티 하나를 가리키는 자리에서 "멤버"로 뭉개지 않는다. 9·10챕터 공통 |
| member constraint | 멤버 제약 | 시그니처의 `when ^a: (member Value: int)`. 기확정 `comparison` 제약 / `equality` 제약 과 계열을 맞춘다. `inline` 함수에서만 걸 수 있다. MS ko 도 "멤버 제약 조건". 9챕터 보충 |
| primitive obsession | 원시 타입 강박 | 도메인 개념 자리에 `int`/`string`/`decimal` 을 그대로 쓰는 상태. 9챕터가 푸는 문제의 이름이며 원서 본문에는 없는 통용 표현(마틴 파울러의 코드 냄새 목록). 리팩터링 한국어판은 "기본형 집착"이나 기확정 `primitive`→원시 타입 과 계열이 맞지 않아 쓰지 않는다. 9챕터 도입부 1회 |
| property | 프로퍼티 | `member this.Value` 처럼 괄호 없이 읽는 멤버. MS ko 는 "속성"이나 기확정 `attribute`→특성 과 나란히 놓으면 속성/특성이 한 글자 차이로 헷갈린다. 커뮤니티 통용 음차를 택한다. 컴파일러·FSI 메시지는 "속성"을 쓰므로(실측: `error FS0806: 'Value'은(는) 정적 속성이 아닙니다.`) 인용은 원문 표기를 그대로 남긴다. `member` 와 갈라 쓴다 — 프로퍼티는 멤버의 한 종류다. 9·10챕터 공통 |
| reference type | 참조 타입 | 힙에 놓이고 `null` 이 들어갈 수 있는 타입. `[<Struct>]` 를 붙이지 않은 판별 유니온·레코드·클래스가 여기 든다. MS ko 는 "참조 형식"이고 이 노트는 형식→타입만 치환해 쓴다. 3·9챕터 |
| single-case discriminated union | 단일 케이스 판별 유니온 | 케이스가 하나뿐인 판별 유니온. 앞의 `\|` 를 생략해 적는 것이 관례다. 원시 타입에 도메인 이름을 붙여 다른 타입으로 만드는 데 쓴다. 7챕터의 단일 케이스 액티브 패턴과 머리 낱말이 겹치므로 "단일 케이스" 한 낱말로 줄이지 않고 언제나 전체 이름으로 쓴다(기확정 `single-case active pattern` 행의 규칙과 짝). 약어(SCDU 등) 쓰지 않는다. 9챕터 본론 |
| smart constructor | 스마트 생성자 | 케이스 식별자를 `private` 으로 막고 검증을 통과한 값만 `Result` 로 돌려주는 생성 함수. 타입의 정적 멤버 형태(`Nights.Create`)와 같은 이름의 모듈 함수 형태(`Nights.create`) 둘이 있다. 정착된 역어가 없으나 "스마트 생성자"가 커뮤니티 통용이다. "똑똑한 생성자"·"스마트 컨스트럭터" 쓰지 않는다. 원서가 케이스 식별자를 "the type constructor"라 부르는 것은 옮기지 않는다 — 함수형 일반 용어에서 type constructor 는 `Option<_>` 처럼 타입을 받아 타입을 만드는 것을 가리키므로 기확정 `case identifier`(케이스 식별자)를 쓴다. 9챕터 본론 |
| static member | 정적 멤버 | `static member Create`. MS ko 표기와 일치. 인스턴스 없이 타입 이름으로 부른다. 9·10챕터 공통 |
| `[<Struct>]` | 구조체 특성 | 특성 이름은 번역하지 않고 `[<Struct>]` 로 쓴다. 붙이면 판별 유니온·레코드가 값 타입이 된다. 서술문에서 결과물을 가리킬 때는 "구조체"(기확정 `struct representation`→구조체 표현 과 계열이 맞다). 다중 케이스 구조체 판별 유니온의 필드 이름 중복 제약(오류 FS3204)은 F# 9 에서 없어졌다(실측: `--langversion:8.0` 까지 FS3204, `9.0` 이후 통과). 9챕터 보충 |
| underlying type | 기반 타입 | 단일 케이스 판별 유니온이 감싼 원래 타입(`Nights of int` 의 `int`), 타입 약어가 별명을 붙인 원래 타입. MS ko 는 문서에 따라 "기본 형식"/"내부 형식"으로 갈리고 이 노트는 "형식"을 쓰지 않는다. "하부 타입"·"기저 타입" 쓰지 않는다(subtype 과 헷갈린다). 9·10챕터 |
| value type | 값 타입 | `[<Struct>]` 를 붙인 타입, `int`/`decimal`/튜플 구조체 등. 기본값이 항상 존재하므로 `Array.zeroCreate`·`Unchecked.defaultof` 로 검증을 거치지 않은 값이 나올 수 있다. MS ko 는 "값 형식"이고 이 노트는 형식→타입만 치환해 쓴다. 3·9챕터 |

## 기확정 변경 제안

없다. 9챕터에서 기확정 표기를 뒤집어야 할 근거를 찾지 못했다.
`primitive`→원시 타입, `case identifier`→케이스 식별자, `type abbreviation`→타입 약어,
`discriminated union`→판별 유니온, `attribute`→특성, `structural equality`→구조적 동등성,
`statically resolved type parameter`→정적으로 확인되는 타입 매개변수 를 9챕터가 모두 그대로 따랐다.
기확정 `single-case active pattern` 행이 예고한 "단일 케이스 한 낱말로 줄이지 않는다" 규칙도
9챕터 전체(11곳)에서 지켜졌다.

## 표기 조정 필요 (용어가 아니라 표기 규칙 — 2b 병합에서 사람이 판단할 것)

1. 원서에 없는 절을 표시하는 꼬리말이 세 갈래로 갈렸다. 하나로 정해야 한다.
   - `(원서에 없음)` — 9챕터 2곳(193행, 425행)
   - `(노트 보충)` / `(노트 보충 — 원서 p.131)` — 10챕터 6곳
   - `(원서에 없는 보충)` — 11챕터 2곳
   - `(원서 p.48 확장)` 계열 — 3·6·8챕터. 이쪽은 "원서의 그 대목을 늘린 것"이라 뜻이 달라 남겨도 된다.
   완전한 신규 절에는 10챕터의 `(노트 보충)` 로 통일하는 것을 권한다(가장 많이 쓰였고 가장 짧다).
   그러면 9챕터 193행·425행, 11챕터 66행·159행을 고쳐야 한다.

2. 2챕터 89행이 `record` 의 field 를 "속성"이라 적었다("레코드와 그 속성은 기본적으로 바뀌지 않는다").
   `property`→프로퍼티 를 확정하면 이 "속성"이 홀로 남은 다른 표기가 된다. 기확정 `field`→필드 가
   있으므로 "레코드와 그 필드는" 으로 고치는 것이 맞다. 9챕터 밖이므로 병합 보고서로 넘긴다.
