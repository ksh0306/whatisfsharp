### 3. `null 허용 참조 타입` (용어집 `nullable reference types`)

- [:126] 현재: "F# 9 부터 켜진 nullable 참조 타입 표기 때문에 `'a | null` 이라는 모양이 보인다."
  용어집 표기는 "null 허용 참조 타입"이다. "nullable 참조 타입"은 용어집에 없는 표기다.
  이 문장은 전문가가 기술 오류로 교체하므로, 교체문(아래 1번)을 쓰면 함께 해소된다. 문장을 부분만 손보는 방식으로 처리하지 마라.

### 6. 병기 점검 결과 (수정 불필요, 확인용)

챕터 안 병기는 전부 1회씩이다. 판별 유니온(3), 계산 식(3), 고차 함수(7), 타입 매개변수(13), `match` 식(40 — 위 1번 적용 후), 와일드카드(40), 레코드(53), 복사-수정 레코드 식(62, 코드 주석), 부분 적용(174), 문(203), 식(203), 스콧 블라신(273), 철도 지향 프로그래밍(273), 익명 함수(314), 자동 일반화(347).
전문가 수정으로 새로 들어오는 병기는 두 개이고 둘 다 챕터 첫 등장이다.
- "null 허용 참조 타입(nullable reference types)" — 126줄 교체문 안에 1회. 다른 곳에 중복 병기 금지.
- "타입 테스트 패턴(type test pattern)" — 227줄 교체문 안에 1회.
새로 들어오는 `Result.toOption`, `--checknulls+`, `nullness` 는 각각 모듈 함수 이름·컴파일러 옵션·용어집이 원어 유지로 못박은 낱말이므로 병기하지 않는다. `nullness` 는 백틱 없이 쓴다(용어집 표기와 동일).

### 7. 판단 보류 (수정하지 않는 것)

- `Nullable<'T>`(111줄)와 `Nullable`(120·149줄): 용어집 표기 열은 `Nullable` 이지만 111줄은 타입 매개변수를 드러내야 하는 자리다. 현행 유지. 전문가가 새로 넣는 문장의 `Nullable<'T>` 표기도 111줄과 일관되므로 그대로 둔다.
- 52줄 "어떤 경우를 버리는지"의 "경우"는 유니온 케이스가 아니라 일반명사다. 다만 417줄을 "케이스"로 고치고 나면 같은 낱말이 두 뜻으로 읽히므로 아래 문법·문체 3번에서 표현을 바꾼다.
- "파이프라인"은 용어집 미등재이나 챕터 안 표기가 일치한다(병합 보고서 5절). 현행 유지.

   (206-214 블록 뒤)
   ```fsharp id=03-exceptions
   // 시그니처가 말하지 않은 실패를 눈으로 확인한다. decimal 나눗셈은 0 으로 나누면 예외다
   // float 는 예외 없이 infinity 를 내므로 이 예제는 decimal 을 쓴다
   try printfn "%M" (divideUnsafe 7M 0M)

   ```
   코드 내용은 전문가안 그대로다(변경 없음). 위치만 옮긴다.

## `tryDivide` 세 판 재배치 (전문가 지시 63-69줄) — 적용형과 경고

### 실행 순서 안전성 검사 결과

같은 `id` 블록은 문서 순서대로 이어 붙어 실행되므로 다음 세 가지만 지키면 재배치로 깨지는 의존 관계는 없다.

- `open System` 이 들어 있는 첫 블록(193-201)은 반드시 맨 앞에 남긴다. `DivideByZeroException` 이 여기에 의존한다.
- `show` 는 `tryDivide` 와 같은 블록에 두고, `show "7/2"` / `show "7/0"` 호출도 같은 블록에 남긴다. 정의가 호출보다 앞이어야 한다.
- 경고: `show` 의 실측 시그니처는 `label: string -> result: Result<decimal,exn> -> unit` 이다. 재배치 후 앞으로 나오는 `tryDivideNarrow` 의 결과는 `Result<decimal,System.DivideByZeroException>` 이므로 `show` 로 출력하면 컴파일되지 않는다. 좁은 판은 지금처럼 `printfn "%b"` 비교로 두고 `show` 를 쓰지 마라.
- 경고: `show` 는 `%-5s` 로 라벨 폭 5를 고정하고 있고 기대 출력 주석("7/2   Ok 3.5")이 그 폭에 맞춰져 있다. 라벨을 `"narrow"` 같은 6자 이상으로 바꾸면 열 정렬과 주석이 동시에 깨진다. 라벨은 5자 이하로 유지하라.

### 적용형 (230-267줄을 아래로 대체)

227·228줄 불릿 뒤에 도입 불릿을 하나 넣고 좁은 판부터 보여 준다.

- 도입 불릿(신규): "- 먼저 반환 타입 주석을 붙이지 않은 판을 본다. 실패 타입은 컴파일러가 `with` 갈래에서 잡은 예외 타입으로 좁혀 추론한다."

```fsharp id=03-exceptions
// 반환 타입 주석이 없는 판. 실패 타입이 잡은 예외 타입으로 좁혀진다
// FSI 실측: x: decimal -> y: decimal -> Result<decimal,System.DivideByZeroException>
let tryDivideNarrow (x: decimal) (y: decimal) =
    try Ok (x / y)
    with :? DivideByZeroException as ex -> Error ex

printfn "%b" (tryDivideNarrow 7M 2M = Ok 3.5M)   // 기대: true
```

251줄의 옛 주석 "// 주석을 떼면 실패 타입이 좁혀진다"는 그대로 두면 안 된다. 재배치 후에는 아직 주석 붙은 판이 나오지 않았으므로 "떼면"이 가리킬 대상이 없다. 위 블록 첫 줄 주석으로 갈아치우라(전문가가 지적하지 않은 자리다).

이어서 267줄을 이 자리로 끌어올리고, 넓히는 두 방법을 예고한다.

- "- 실패 타입을 좁게 두면 그 함수 하나를 볼 때는 정보가 많아 좋다. 하지만 여러 단계를 이어 붙이려면 단계마다 실패 타입이 같아야 하므로, 파이프라인 전체가 공유하는 실패 타입을 미리 정해 두는 편이 편하다."
- "- 넓히는 방법은 두 가지다. 반환 타입을 `Result<decimal, exn>` 으로 주석하거나, `Error` 에 담을 때 `ex :> exn` 으로 상향 변환한다."
  (여기서 `Result.bind` 를 앞당겨 언급하지 마라. `bind` 는 다음 절 373줄에서 처음 소개된다.)

```fsharp id=03-exceptions
// 반환 타입 주석으로 실패 타입을 exn 으로 넓힌 판
// FSI 실측: numerator: decimal -> denominator: decimal -> Result<decimal,exn>
let tryDivide (numerator: decimal) (denominator: decimal) : Result<decimal, exn> =
    try
        Ok (numerator / denominator)
    with
    | :? DivideByZeroException as ex -> Error ex

// FSI 실측: label: string -> result: Result<decimal,exn> -> unit
let show label result =
    match result with
    | Ok value -> printfn "%-5s Ok %M" label value
    | Error (ex: exn) -> printfn "%-5s Error %s" label (ex.GetType().Name)

show "7/2" (tryDivide 7M 2M)   // 기대: 7/2   Ok 3.5
show "7/0" (tryDivide 7M 0M)   // 기대: 7/0   Error DivideByZeroException
```

- 248줄 서술은 순서가 바뀌었으니 문장도 바꾼다. 현재: "- 반환 타입 주석 `: Result<decimal, exn>` 을 일부러 달았다. 주석을 떼면 F# 10 컴파일러는 실패 타입을 `exn` 이 아니라 `DivideByZeroException` 으로 좁혀 추론한다. 원서 주석에는 `Result<decimal,exn>` 이라 적혀 있으니 대조하며 읽을 때 혼동하지 않도록 실측값을 함께 남긴다."
  → 수정: "- 원서 주석에는 `Result<decimal,exn>` 이라 적혀 있다. F# 10 컴파일러는 반환 타입 주석이 없으면 실패 타입을 `DivideByZeroException` 으로 좁히므로, 대조하며 읽을 때 혼동하지 않도록 두 판을 나란히 남겼다."
- 원서 오기 메모(전문가 지시 104-107줄)를 여기에 붙인다: "- 원서 p.45 의 `// Some 1M` 주석은 `// Ok 1M` 의 오기다. 그 시점 `tryDivide` 는 `Option` 이 아니라 `Result` 를 낸다."

```fsharp id=03-exceptions
// 명시적 상향 변환으로 넓힌 판. 반환 타입 주석 없이도 실패 타입이 exn 이 된다
// FSI 실측: x: decimal -> y: decimal -> Result<decimal,exn>
let tryDivideWide (x: decimal) (y: decimal) =
    try Ok (x / y)
    with :? DivideByZeroException as ex -> Error (ex :> exn)

printfn "%b" (tryDivideWide 7M 2M = Ok 3.5M)   // 기대: true
```

- 절을 닫는 문장(전문가안): "- 세 판은 같은 계산이고 다른 것은 실패 타입뿐이다. 파이프라인에 넣을 것은 실패 타입이 `exn` 으로 통일된 판이다."
  이 문장이 다음 절("## Function Composition With Result")로 자연스럽게 이어진다. 267줄이 비므로 절 끝에 다른 불릿을 남기지 마라.

정렬 확인: 원래 263-264줄은 두 `printfn` 이 나란히 있어 넓은 판 쪽에 공백 5칸을 넣어 열을 맞췄다. 재배치로 두 줄이 다른 블록으로 갈라지므로 각각 공백 3칸("...Ok 3.5M)   // 기대: true")으로 적어야 블록 안에서 어색하지 않다. 위 코드가 그 형태다.
`tryDivideWide` 의 주석 "명시적 상향 변환으로..."는 주석 붙은 판이 앞에 오는 순서를 전제한다. 좁은 판 → 주석 판 → 상향 변환 판 순서를 지켜라. 순서를 바꾸면 이 주석의 "~없이도"가 성립하지 않는다.

## 선행 검수 지시서의 문제

### 1. [수정 필요 1항 / 126줄 교체문] 교체 범위가 불분명하고 옵션 서술이 모호하다

전문가안: "`ofObj`/`toObj` 는 참조 타입에만, ... 켜려면 `--checknulls+` 를 준다."
현재 126줄은 문장 넷으로 되어 있고 앞의 두 문장("`Option` 모듈의 변환 함수 네 개다. 시그니처는 FSI 로 실측한 값이며, 제약이 붙어 있다는 점이 중요하다.")은 유지 대상이다. 그대로 이어 붙이면 앞 두 문장이 중복될 수 있다.
→ 수정형(126줄 문단 전체를 이것으로 바꾼다):
"`Option` 모듈의 변환 함수 네 개다. 시그니처는 FSI 로 실측한 값이며, 제약이 붙어 있다는 점이 중요하다. `ofObj`/`toObj` 는 참조 타입에만, `ofNullable`/`toNullable` 은 값 타입에만 쓸 수 있다. `'a | null` 은 F# 9 에서 들어온 null 허용 참조 타입(nullable reference types) 표기이고, FSharp.Core 시그니처에 nullness 정보가 붙어 있어 이렇게 보인다. `'a` 또는 `null` 로 읽으면 된다. 검사 자체는 기본으로 꺼져 있어 앞 블록의 `missingNickname` 바인딩이 경고 없이 통과한다. 켜려면 컴파일러나 FSI 에 `--checknulls+` 옵션을 준다."
바뀐 점: (a) "위의 `null` 바인딩" → "앞 블록의 `missingNickname` 바인딩"(줄 번호는 편집으로 밀리므로 식별자로 가리킨다), (b) "`--checknulls+` 를 준다" → "컴파일러나 FSI 에 `--checknulls+` 옵션을 준다"(무엇에 주는지 명시).
경고 번호를 본문에 적을 경우 표기는 "경고 FS3261"로 한다(01챕터 254줄 "경고 FS0025"와 같은 형태). `warning FS3261: Nullness warning: ...` 처럼 영문 메시지를 그대로 옮기지 마라. 안 적어도 된다.
"옵트인"이라는 낱말은 본문에 쓰지 마라(용어집 비고에만 있는 말이고 병기 없이 쓰면 뜬다). 위 문장처럼 "기본으로 꺼져 있다"로 서술한다.

### 2. [수정 필요 3항 / 23줄 교체문] 그대로 쓸 수 있다. 한 군데만 다듬는다

전문가안: "... `let mutable` 값을 만들어 `&value` 로 직접 넘기는 길도 있지만, 튜플로 받는 쪽이 관용적이다."
→ 수정형: "- `Option` 이 처음 등장하는 자리는 .NET 의 `TryParse` 계열이다. F# 에는 `out` 매개변수를 선언하는 문법이 없어서, 상호운용에서는 컴파일러가 `out` 매개변수를 반환값 쪽으로 옮겨 붙여 준다. 그 결과 `DateTime.TryParse` 는 `bool * DateTime` 튜플을 돌려준다. `let mutable` 값을 만들어 `&value` 로 직접 넘길 수도 있지만, 튜플로 받는 쪽이 관용적이다."
바뀐 점: 불릿 기호 `- ` 를 붙였다(23줄은 불릿이다). "넘기는 길도 있지만" → "넘길 수도 있지만"(같은 문단에서 "길"이 은유로 두 번 쓰이는 것을 피한다). 용어 표기(`out` 매개변수, 상호운용)는 용어집과 일치한다.

### 3. [수정 필요 4항 / 227줄 교체문] 용어집 위반 1건, 오독 유발 2건

전문가안: "- `try/with` 안의 `:?` 는 타입 테스트 패턴(type test pattern)이다. 던져진 예외가 적은 타입이거나 그 하위 타입인지를 런타임에 검사할 뿐 값을 변환하지 않는다. 일치하면 `as ex` 가 그 타입으로 좁혀진 예외 인스턴스를 묶어 주고, 이것을 `Error` 의 경우 데이터로 넘긴다."
문제: (a) "경우 데이터"는 용어집 위반이다 → "케이스 데이터"(병합 보고서 2.2). (b) "적은 타입"이 수량의 "적은"으로 읽힌다. (c) "인스턴스를 묶어 주고"는 `as` 바인딩을 가리키기에 부적절하다(용어집 `binding`=바인딩).
→ 수정형: "- `try/with` 안의 `:?` 는 타입 테스트 패턴(type test pattern)이다. 던진 예외가 `:?` 뒤에 적어 둔 타입이거나 그 하위 타입인지를 런타임에 검사할 뿐, 값을 변환하지는 않는다. 일치하면 `as ex` 가 그 타입으로 좁혀진 예외 인스턴스를 `ex` 에 바인딩하고, 그 값을 `Error` 의 케이스 데이터로 넘긴다."

### 4. [수정 필요 2항 / 487줄 교체문과 추가 블록] 주술 불일치 1건, 주석 형식 1건

전문가안: "- 반대 방향에는 표준 함수가 있다. `Result.toOption` 은 `Ok` 안의 값을 `Some` 으로 옮기고 `Error` 는 이유를 버린 `None` 이 된다. 실패 이유를 버리는 것이 의도일 때만 쓴다."
문제: 한 문장 안에서 주어가 `Result.toOption` → `Error` 로 갈리는데 서술어가 이어져 주술이 어긋난다.
→ 수정형: "- 반대 방향에는 표준 함수가 있다. `Result.toOption` 은 `Ok` 안의 값을 `Some` 으로 옮기고, `Error` 는 이유를 버려 `None` 으로 바꾼다. 실패 이유를 버리는 것이 의도일 때만 쓴다."

```fsharp id=03-result-errors
// FSI 실측: Result.toOption : Result<'a,'b> -> 'a option
```

정렬 확인: 두 `printfn` 의 `//` 열이 맞는다(3칸/6칸). 그대로 쓰면 된다. 이 블록은 `upload` 를 쓰므로 `03-result-errors` 의 448줄 블록보다 뒤에 놓아야 한다. 476-485줄 블록 뒤가 맞다.

### 8. [개선 권장 / 113-115줄 `Option.defaultWith`] 챕터 표기 위반과 정렬

전문가 문장의 "08챕터"는 STYLE 금지 패턴(`N챕터` 통일)에 걸린다. 노트 본문은 "8챕터"로 쓴다(3·504줄).
→ 수정형. 76-80줄 시그니처 블록에 한 줄을 더하고, 84줄 불릿 뒤에 불릿 하나를 넣는다.

시그니처 블록(콜론 열을 21칸에 맞춘 형태다. `Option.defaultWith` 는 `Option.defaultValue` 보다 한 자 짧으므로 공백 두 칸이다):
```fsharp
Option.map          : ('a -> 'b) -> 'a option -> 'b option
Option.bind         : ('a -> 'b option) -> 'a option -> 'b option
Option.defaultValue : 'a -> 'a option -> 'a
Option.defaultWith  : (unit -> 'a) -> 'a option -> 'a
```
불릿: "- `Option.defaultValue` 는 기본값을 먼저 평가한다. 기본값을 만드는 데 비용이 들면 `Option.defaultWith` 를 쓴다. 8챕터의 검증 파이프라인에서 다시 만난다."
(74줄의 "세 함수의 시그니처를 FSI 로 실측한 값은 다음과 같다"도 함께 고쳐야 한다 → "네 함수의 시그니처를 FSI 로 실측한 값은 다음과 같다". 이 항목을 적용하지 않기로 하면 74줄은 그대로 둔다.)

### 9. [개선 권장 / 117-120줄, 100-101줄 주석] 그대로 쓸 수 있다

- `Option` 정의 블록에 넣을 주석: "// 실제 정의는 None 이 먼저다" (백틱 없이. 용어집 `Option` 비고와 같은 서술이다.)
- 42-48줄 블록에 넣을 주석: "// | _ -> None 으로 줄여도 같다. 튜플 전체가 와일드카드 하나에 걸린다" — 백틱 없고 평서형이며 그대로 쓸 수 있다. 40줄 산문이 이미 같은 내용을 말하므로 중복 서술이 되지 않게 40줄은 손대지 말고 주석만 넣는다.
