## 용어 일관성

### 1. `stubReader` → `fakeReader` (용어집 `fake (test double)`: 식별자도 `fake` 로 시작하게 짓는다)

이 식별자가 쓰인 자리는 파일 전체에서 세 곳뿐이다(기계 확인: `grep -n stubReader` → 512, 522, 564).
정의·호출·본문 서술이 각각 한 번씩이고 기대 출력 주석·`printfn` 문자열에는 나오지 않으므로,
아래 셋을 고치면 남는 자리가 없다.

- [06:512] 현재: `let stubReader: DataReader =`
  수정: `let fakeReader: DataReader =`
- [06:522] 현재: `import stubReader "(이 경로는 쓰이지 않는다)"`
  수정: `import fakeReader "(이 경로는 쓰이지 않는다)"`
- [06:564] 본문. 아래 "문법·문체" 절의 564줄 수정형에 이미 반영해 두었다(같은 문장을 두 번 고치지 마라).

라벨 폭 영향 없음: 두 줄 모두 `printfn` 이 아니고, 511줄 주석과 521·524줄의 `"가짜 리더:"` 는
그대로 두면 되므로 열 정렬이 깨지지 않는다.

### 2. [06:53] `정리된다` → `해제된다` (용어집 `dispose` → 해제한다)

고칠 "정리"는 53줄 하나뿐이다. `Dispose()` 호출을 가리키는 자리이기 때문이다.
아래 세 종류의 "정리"는 그대로 둔다(병합 보고서 2.2 와 같은 판단이다).

- 104·196·561줄 `printfn "임시 파일 정리: %b"` 와 짝이 되는 기대 출력 주석 — `File.Delete` 로
  임시 파일을 치우는 것이므로 진짜 "정리"다. 문자열 폭이 바뀌지 않으니 열 정렬도 그대로다.
- 578줄 절 제목 `## 정리 — 이 노트의 요약` — 8개 노트가 공유하는 제목이다.
- 5줄 "용어 셋을 정리해 둔다" — 일반 동사다.

53줄은 전문가의 `use` 스코프 보강 지시와 겹친다. 최종 문장은 이것 하나로 넣어라.

현재: "- `StreamReader` 는 `IDisposable` 을 구현한다. `use` 로 바인딩하면 스코프가 끝날 때 `Dispose()` 가 호출된다. C# 의 `using` 문에 대응한다. 여기서 스코프는 들여쓰기가 정한 시퀀스 식 안쪽이고, 시퀀스 순회가 끝나는 시점에 정리된다."
수정: "- `StreamReader` 는 `IDisposable` 을 구현한다. `use` 로 바인딩하면 스코프가 끝날 때 `Dispose()` 가 호출된다. C# 의 `using` 문에 대응한다. 여기서 스코프는 들여쓰기가 정한 시퀀스 식 안쪽이고, 시퀀스 순회가 끝나는 시점에 해제된다. 순회를 중간에 끊어도 끊는 자리에서 해제된다. 반대로 한 번도 순회하지 않으면 이 줄 자체가 실행되지 않아 파일이 열리지도 않는데, 그 성질이 다음 절의 함정을 만든다."

전문가안의 "열거자가 정리되는 시점에 불린다"를 그대로 쓰면 안 되는 이유는 두 가지다.
(1) "정리"를 `Dispose()` 뜻으로 다시 쓰게 되어 이 항목의 수정 자체를 무효로 만든다.
(2) "불린다"의 주어(`Dispose()`)가 두 문장 앞에 있어 문장만으로는 읽히지 않는다.
덧붙여 "열거자"는 용어집에 없는 표기다. 위 수정형은 그 낱말을 쓰지 않고 같은 사실을 전한다.

### 병기

현재 병기는 다섯 곳이다 — 7줄 `시퀀스 식(sequence expression)`, 8줄 `지연 평가(lazy evaluation)`,
9줄 `부분 함수(partial function)`·`부분 적용(partial application)`, 442줄 `타입 약어(type abbreviation)`.
중복 병기는 없다(같은 용어가 두 번 병기된 곳 0건, 기계 확인).

용어집 `partial function` 이 요구하는 형식은 지켜졌다. 9줄이 첫 등장에서 `부분 함수(partial function)` 로
병기하고, 같은 챕터에 부분 적용이 나오므로 "이름이 비슷한 부분 적용(partial application)과는 아무 관계가
없다"를 덧붙였다. 286·586줄은 한국어만 쓰고 "부분"으로 줄여 쓴 곳도 없다. 손대지 마라.

## 문법·문체

- [06:3] "이 챕터는 … 데이터를 들여온다"는 주술 불일치다(STYLE 금지 패턴 2). 마지막의 "다시 다룬다"도
  틀렸다. 이 문장이 8챕터 검증을 꺼내는 첫 자리이므로 "다시"가 걸 대상이 없다.
  현재: "> 이 챕터는 3챕터의 `Result` 와 5챕터의 컬렉션을 합쳐 바깥 세계의 데이터를 프로그램 안으로 들여온다. … 파싱한 결과를 문자열 그대로 두는 원서의 선택도 의도된 것이며, 실패 이유를 남기는 검증은 8챕터에서 다시 다룬다."
  수정: "> 이 챕터에서는 3챕터의 `Result` 와 5챕터의 컬렉션을 합쳐 바깥 세계의 데이터를 프로그램 안으로 들여온다. 소재는 구분자로 나뉜 텍스트 파일 하나지만, 얻어 가야 할 것은 두 가지다. 하나는 지연 평가되는 시퀀스를 `try/with` 로 감싸면 예외를 놓친다는 사실이고, 다른 하나는 데이터 출처를 함수 매개변수로 빼면 파일 없이도 테스트할 수 있다는 설계다. 파싱한 결과를 문자열 그대로 두는 원서의 선택도 의도된 것이며, 실패 이유를 남기는 검증은 8챕터의 몫이다."

- [06:14] "돌려주는 것은 … 종료 코드다"로 주어와 서술어가 어긋난다. 종료 코드인 것은 반환 행위가 아니라 값이다.
  현재: "- `main` 이 마지막에 `0` 을 돌려주는 것은 프로세스 종료 코드다. F# 6 부터는 …"
  수정: "- `main` 이 마지막에 돌려주는 `0` 은 프로세스 종료 코드다. F# 6 부터는 `[<EntryPoint>]` 를 붙이지 않아도 되고, 마지막 코드 파일의 최상위 코드가 그대로 진입점이 된다."

- [06:76] "동작을 수행하고"는 영어 perform 직역이고, 둘째 문장은 주어가 뒤로 밀려 읽기 어렵다.
  현재: "`Seq.iter` 는 원소마다 동작을 수행하고 `unit` 을 돌려준다. `List` 나 `Array` 모듈과 이름이 같은 함수가 `Seq` 모듈에도 대부분 들어 있다."
