# 11챕터 용어 후보 (F# 전문가 검수, 후보 모드)

`docs/ko/GLOSSARY.md` 는 읽기만 했고 편집하지 않았다(다른 챕터 전문가와 동시 작업 중).
아래 행을 알파벳 순 위치에 그대로 삽입하면 된다. 기확정 항목 변경 제안은 없다.

## 확정 제안 (그대로 삽입)

| 영어 | 한국어 표기 | 비고 |
|---|---|---|
| base case | 기저 경우 | 재귀가 멈추고 값을 내놓는 갈래. 짝은 재귀 경우(recursive case). "기본 경우"·"종료 조건"·"베이스 케이스" 쓰지 않는다. 기저 경우를 적는 것과 입력이 그 갈래에 닿는 것은 다른 문제다. 11챕터 본론 |
| `bigint` | `bigint` | 번역하지 않는다. `System.Numerics.BigInteger` 의 F# 별칭이고 표현 범위 제한이 없는 정수 타입. 리터럴 접미사는 `I`(`42I`). 11챕터 |
| exhaustive search | 완전 탐색 | 가능한 후보를 모두 만들어 보고 그중에서 고르는 방식. 기확정 "빠짐없는 패턴 매칭(exhaustive pattern matching)"과 영어 낱말이 겹치므로 알고리즘 쪽은 "완전 탐색"으로만 쓰고 "빠짐없는 탐색" 쓰지 않는다. 11챕터 |
| hierarchical data | 계층 데이터 | 트리처럼 자기 자신을 품는 구조의 데이터. "계층형 데이터"·"위계 데이터" 쓰지 않는다. 원서 절 제목 Recursion with Hierarchical Data(원서 p.146). 11챕터 본론 |
| identity element | 항등원 | 어떤 값에 적용해도 값을 바꾸지 않는 값. 누적값과 `fold` 의 초기값을 정하는 기준이다(곱셈 `1`, 덧셈 `0`, 문자열 이어 붙이기 `""`). 수학에서 정착된 표기를 그대로 쓴다. 기확정 "항등 함수(identity function)"와는 다른 것이므로 같은 문장에서 섞어 쓰지 않는다. 5챕터·11챕터가 이미 이 표기를 쓴다 |
| mutual recursion | 상호 재귀 | 두 함수가 서로를 부르는 재귀. `let rec f ... and g ...` 로 잇는다. MS ko 표기와 일치. `rec` 없이 `and` 만 쓰면 오류 FS0576(실측). 타입 정의에도 같은 `and` 를 쓴다. 11챕터 보충 절 |
| overflow (arithmetic) | 넘침 | 계산 결과가 타입의 표현 범위를 벗어나는 것. F# 기본 산술 연산자는 넘침을 검사하지 않고 값이 감싸 돈다. 검사판은 `open Microsoft.FSharp.Core.Operators.Checked` 로 켠다(실측: `Int64.MaxValue + 1L` 이 `OverflowException`). MS ko 는 "오버플로"이나, 이 노트는 "오버플로"를 스택 오버플로에만 남기고 산술 쪽은 "넘침"으로 갈라 쓴다 |
| quicksort | 퀵소트 | 정착된 음차. "빠른 정렬"·"퀵 소트" 쓰지 않는다. 원서 절 제목 표기는 Quicksort(원서 p.145). 11챕터 |
| `rec` | `rec` | 키워드는 번역하지 않는다. `let rec` 로 선언해야 함수 본문에서 자기 이름을 볼 수 있고, 빼면 오류 FS0039(실측). "재귀 키워드"로 풀어 쓰는 것은 허용 |
| recursion | 재귀 | 정착된 한국어. 함수는 "재귀 함수", 자기 타입을 품는 정의는 "재귀형"(재귀형 판별 유니온), 갈래는 "재귀 경우". "되부름"·"리커전" 쓰지 않는다 |
| recursive case | 재귀 경우 | 자기를 다시 부르는 갈래. 기저 경우와 짝. 원서는 general case 라고 부르지만(원서 p.141) 노트는 기저 경우와 대비가 분명한 "재귀 경우"를 쓴다 |
| stack frame | 스택 프레임 | 호출 하나가 스택에 잡는 자리. 돌아갈 자리와 그 호출의 지역 값이 여기 들어간다. MS ko 표기와 일치. 음차 고정하고 "스택 틀" 쓰지 않는다 |
| stack overflow | 스택 오버플로 | 스택 프레임이 한계를 넘는 것. .NET 의 `StackOverflowException` 은 `try ... with` 로 잡을 수 없고, 런타임이 표준 오류에 `Stack overflow.` 를 찍고 프로세스를 끝낸다(실측: 종료 코드 134). 외래어 표기법대로 "오버플로우" 아닌 "오버플로". 산술 쪽 overflow 는 "넘침"으로 갈라 쓴다 |
| `[<TailCall>]` | `[<TailCall>]` | 특성 이름은 번역하지 않는다. F# 8 부터 컴파일러가 꼬리 호출 여부를 검사해 아니면 경고 FS3569 를 낸다. 실측한 제약 세 가지 — 프로젝트 빌드에서만 검사하고 `dotnet fsi` 스크립트에서는 검사하지 않으며, `--langversion:7.0` 에서는 검사하지 않고, 지역 `let rec` 에는 붙일 수 없다(오류 FS0010) |
| tail call | 꼬리 호출 | 함수가 마지막으로 하는 일이 어떤 호출이고 그 결과가 곧 그 함수의 반환값인 경우. 재귀 호출일 필요는 없다. MS ko 표기와 일치 |
| tail call optimisation | 꼬리 호출 최적화 | 꼬리 호출에서 프레임을 새로 쌓지 않는 것. 원서 표기는 영국식 optimisation(원서 p.142). 약어 TCO 는 쓰지 않는다. 실측 근거 — 자기 자신을 직접 부르는 꼬리 호출은 컴파일러가 반복문으로 바꾸므로 `--tailcalls-` 인 Debug 프로젝트 빌드에서도 성립하고, 상호 재귀처럼 다른 함수로 가는 꼬리 호출은 `--tailcalls+` 일 때만 성립한다(`dotnet fsi` 와 Release 는 통과, Debug 빌드는 1000만 호출에서 스택 오버플로) |
| tail recursion | 꼬리 재귀 | 재귀 호출이 꼬리 호출인 재귀. 기확정 `tail`(리스트의 꼬리)과 낱말이 같고 개념이 다르므로, 리스트를 분해하는 문맥에서는 분해한 나머지를 `rest` 로 적고 둘이 다른 말이라는 것을 한 문장으로 갈라 둔다(`tail` 행과 짝) |
| traversal | 순회 | 트리나 컬렉션을 훑는 것. "트리 순회". search 쪽에 "탐색"을 남겨 두기 위해 traversal 은 "탐색"으로 옮기지 않는다 |

## 기확정 용어 확인 사항 (표에 넣지 않음)

- `Map` (collection type) 은 이미 확정돼 있고 비고에 "맵"·"사전" 쓰지 않음이 적혀 있다.
  11챕터가 `Map` 을 처음 실제로 쓰는 챕터인데 본문 두 곳에서 "사전"으로 풀어 썼다.
  용어집이 아니라 노트를 고쳐야 한다(검수 보고서 `수정 필요` 참조).
- `accumulator`→누적값, `partial function`→부분 함수, `partial application`→부분 적용,
  `predicate`→술어, `discriminated union`→판별 유니온, `fold`/`folder`, `exit code`→종료 코드는
  기확정 표기를 그대로 따르고 있다. 변경 제안 없다.
- `tail` 행의 "11챕터의 꼬리 재귀와 같은 낱말이나 다른 개념이므로 그 챕터에서 구분해 쓴다" 는
  요구는 11챕터가 지키고 있다(구분 문장 + 분해 변수 `rest`).
